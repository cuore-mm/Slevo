## Context

タブ一覧の下部操作群は `TabScreenContent` の `bottomBar` として重畳されるため、背景リストの文字やアクセントカラーと干渉しやすい。既存は枠線・シャドウ・サーフェス色で視認性を確保しているが、スクロール位置やカード色によってコントラストが不足するケースがある。

本変更では `haze` の Masking を活用し、下部操作群の背面に段階的なぼかしをかける。さらに、板ページとスレページで表示ボタン数が異なる状態でも、下段の3スロットレイアウト（左予備、中央作成、右更新）を固定して、操作位置の学習コストを増やさない。

## Goals / Non-Goals

**Goals:**
- タブ一覧下部操作群に Haze を適用し、背景ノイズの多い場面でも文字とアイコンの可読性を維持する。
- Masking で下端に向かってぼかし効果が強くなるグラデーション表現を実現する。
- 板/スレ切替時にボタン位置を固定し、表示/非表示のみを切り替える。
- 既存の遷移・作成・更新契約を維持したまま視認性のみ改善する。

**Non-Goals:**
- タブ一覧以外の画面に Haze を展開すること。
- ボタンの機能契約やページ構成を変更すること。
- 新しい左スロット機能（その他ボタン）の実装。

## Decisions

- `TabScreenContent` で `hazeState` を生成し、`TabsPagerContent` 側を haze source、`TabListBottomControls` 側を haze child とする。
  - 代替案: `TabListBottomControls` 内で独立してぼかしを定義する。
  - 不採用理由: ぼかし対象の背面コンテンツはページャー側にあるため、親画面で source を管理した方が責務が明確。

- Haze の Masking は「上側が弱く下側が強い」縦方向グラデーションで適用する。
  - 代替案: 一様な blur 半径のみで表現する。
  - 不採用理由: 一様 blur は境界が硬く見えやすく、下部固定操作群としての自然な視線誘導を作りにくい。

- 下部ボタン列は常に3スロットを維持し、未実装スロットと板ページ更新枠は同サイズプレースホルダーで確保する。
  - 代替案: 表示ボタン数に応じて `Arrangement` を切り替える。
  - 不採用理由: ページ切替ごとに位置が動き、操作の筋記憶を阻害する。

- Haze 適用後も下部サーフェスと丸形ボタンの外周に境界線を残す。
  - 代替案: ぼかしのみで境界を表現する。
  - 不採用理由: 明度差が小さい背景で境界が溶けるため、操作面の輪郭が不安定になる。

## Risks / Trade-offs

- [リスク] 低スペック端末で blur 描画コストが増加する。 → [緩和策] blur 半径とマスク強度を段階的に調整し、必要なら効果を弱める。
- [リスク] マスクの方向や強度が強すぎると背面コンテンツが読めなくなる。 → [緩和策] スクリーンショット比較で閾値を決め、可読性を優先した値を固定する。
- [トレードオフ] 見た目は向上するが、実装依存（haze API）への追従コストが増える。 → [緩和策] Haze 関連ロジックを `TabScreenContent` と `TabListBottomControls` に限定し、影響範囲を狭める。
