## Context

板画面には既存の `BoardInfoDialog` と `showInfoDialog` 状態があるが、ボトムバーのタイトルカードから呼び出されておらず、Issue #484 が求めるボトムシート体験にもなっていない。一方、スレッド情報は `ThreadInfoBottomSheet` として実装済みで、タイトル、メタ情報、アクションボタングリッド、コピー用ダイアログ、外部ブラウザ起動、共有を 1 つのコンポーザブル内で扱っている。

今回の変更では、スレッド情報シートの表示構造を共通化し、板情報シートでも同じレイアウトと操作体験を利用する。アプリケーションコードの実装時は既存の MVVM 構造に沿い、板情報シートの表示状態は `BoardViewModel` が所有する `BoardUiState` に保持する。

## Goals / Non-Goals

**Goals:**

- 板画面のボトムバータイトルカードをタップすると、板情報ボトムシートを表示する。
- 板情報ボトムシートでは、タイトルとして板名、サブ情報としてサービス名を表示する。
- 板情報ボトムシートのアクションはコピー、外部ブラウザで開く、共有の 3 つに限定する。
- `ThreadInfoBottomSheet` のタイトル・サブ情報・アクションボタン表示を共通コンポーネントへ切り出し、スレッド情報シートと板情報シートで再利用する。
- 既存のスレッド情報シートの表示内容と操作は維持する。

**Non-Goals:**

- 板情報に新しい永続化項目を追加しない。
- ブックマーク、NG登録、板遷移など、Issue #484 で指定されていない板情報シートの追加アクションは実装しない。
- 外部ブラウザ起動や共有の仕組み自体は再設計しない。
- スレッド一覧やスレッド画面のナビゲーション仕様は変更しない。

## Decisions

### 1. 共通UIは情報シート本文とアクショングリッドに分ける

`ThreadInfoBottomSheet` から、タイトル、サブ情報、区切り線、アクションボタンカードを描画する共通コンポーネントを切り出す。共通化対象は表示構造に限定し、スレッドURL生成、板URL利用、コピー項目生成、外部ブラウザ起動、共有 Intent の起動などの画面固有処理は各シートのラッパー側に残す。

代替案として `ThreadInfoBottomSheet` 自体に板用パラメータを追加する方法もあるが、スレッド固有のレス数・日付・勢い・NG登録・板遷移と、板固有のサービス名表示が混在して分岐が増えるため採用しない。

### 2. 板情報シートは `BoardInfoBottomSheet` として新規作成する

`BoardInfoBottomSheet` は `SlevoBottomSheet` を利用し、表示状態、閉じる処理、コピー用ダイアログ、外部ブラウザ起動、共有を制御する。本文は共通情報シートUIに板名、サービス名、3つのアクションを渡して構成する。

板URLが空の場合は外部ブラウザ起動を行わず、既存の無効URLトーストと同等のフィードバックを出す。コピーと共有は板URLを対象にし、コピーでは板名、URL、板名とURLの組み合わせを選べるようにする。

### 3. 板情報表示状態は Dialog 名称から Sheet 名称へ置き換える

`BoardUiState.showInfoDialog` と `BoardViewModel.openInfoDialog` / `closeInfoDialog` は、シートを表す `showBoardInfoSheet` と `openBoardInfoSheet` / `closeBoardInfoSheet` へ置き換える。UI状態名を表示形式に合わせることで、今後の保守時に Dialog と Sheet の混同を避ける。

既存の `BoardInfoDialog` は使用箇所がなくなる見込みのため削除候補とする。削除する場合は参照が残っていないことを確認する。

### 4. タイトルカードタップの接続は `BoardScaffold` で行う

`TabToolBar` にはすでに `onTitleClick` が存在するため、板画面側では `onTitleClick = { viewModel.openBoardInfoSheet() }` を設定する。これによりツールバー共通部には追加変更を入れず、板画面固有の挙動としてシート表示を接続する。

## Risks / Trade-offs

- 共通コンポーネントの抽象度が高すぎると、スレッド情報シート側の可読性が下がる。 → 共通化は「表示構造」と「アクションボタン表示」に限定し、画面固有ロジックは各シートに残す。
- `ThreadInfoBottomSheet` の既存挙動を壊す可能性がある。 → スレッド側の表示項目、アクション、`showBoardAction` の分岐を維持し、既存プレビューと必要なテストで確認する。
- サービス名が空の状態でシートを開く可能性がある。 → `BoardUiState.serviceName` をそのまま表示し、空の場合でもクラッシュしない構成にする。必要に応じてURL由来のサービス名補完を表示側で検討する。
- 外部ブラウザや共有の起動は端末環境に依存する。 → 既存の `ExternalBrowserUtil` と Intent chooser の使い方に揃え、失敗時は既存メッセージを表示する。
