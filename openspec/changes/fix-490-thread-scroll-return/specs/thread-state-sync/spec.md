## ADDED Requirements

### Requirement: 連続スクロール中のタブスクロール位置保存
システムは開いているスレッドタブのスクロール位置を、手動スクロール中だけでなく自動スクロールのように位置が連続更新される状態でも、復元に利用できる最新位置として保存しなければならないMUST。保存処理は連続更新が停止することを前提にしてはならないMUST NOT。

#### Scenario: 自動スクロール中にタブを切り替える
- **WHEN** ユーザーがスレッド画面で自動スクロールを有効にしたまま別のスレッドタブへ切り替える
- **THEN** システムは切り替え時点のスクロール位置を対象スレッドタブの保存済みスクロール位置として反映する

#### Scenario: 自動スクロール中に他画面へ遷移する
- **WHEN** ユーザーがスレッド画面で自動スクロールを有効にしたまま他の画面へ遷移する
- **THEN** システムは遷移時点のスクロール位置を対象スレッドタブの保存済みスクロール位置として反映する

#### Scenario: 自動スクロール後に元のスレッドへ戻る
- **WHEN** ユーザーが自動スクロール中に画面を離れたあと元のスレッド画面へ戻る
- **THEN** システムは画面を離れた時点の保存済みスクロール位置でスレッドを復元する

### Requirement: スレッド投稿行の安定識別
システムはスレッド投稿一覧の各投稿行を、表示中の行インデックスではなく、投稿を表すレス番号と表示上の役割を組み合わせた安定識別子で識別しなければならないMUST。同じレス番号の投稿が通常行と文脈表示行として複数回現れる場合でも、各行の key はリスト内で一意でなければならないMUST。

#### Scenario: 投稿行の表示位置が変わる
- **WHEN** 新着取得、表示更新、またはフィルタ状態の変化により投稿行の表示位置が変わる
- **THEN** システムは行インデックスに依存しない key を使用する

#### Scenario: 同じレス番号の投稿行が複数回表示される
- **WHEN** ツリー表示や新着境界の文脈表示により、同じレス番号の投稿が通常行と dimmed 行など複数の行として表示される
- **THEN** システムはレス番号に表示上の役割を組み合わせ、各投稿行を一意な key で識別する

#### Scenario: 投稿行の表示役割が変わる
- **WHEN** 投稿行が通常表示、dimmed 表示、新着側文脈表示、異なるツリー深さとして表示される
- **THEN** システムは同じレス番号でも表示上の役割が異なる行を区別できる key を使用する
