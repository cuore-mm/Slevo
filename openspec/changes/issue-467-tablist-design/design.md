## Context

Issue #467 は、タブ一覧ボトムシートにおける情報密度と操作導線の再設計を求める変更である。現状は `TabRow` が上部、URL入力の FAB が右下、スレッド更新がプル更新に分散しており、一覧確認とアクション実行を一連で行いにくい。加えて、板一覧とスレ一覧で行コンポーネント構造が異なるため、見た目と認知モデルが統一されていない。

本変更は `ui/tabs` 配下を中心に UI を再構成し、既存の遷移契約（タップで対象タブへ遷移、×でタブクローズ）を維持したまま、カード表示と下部2段操作群に統一する。

## Goals / Non-Goals

**Goals:**
- 板/スレ両方のタブ一覧アイテムをカード状レイアウトへ統一する。
- アイテム上段にサービス名・板名・レス数・閉じるボタンを配置し、情報確認とクローズ操作を同一視線内で完結させる。
- スレッド新着表示を板画面と同様のバッジ表現へ統一する。
- 操作群を下部2段に集約し、上段に板/スレ切替、下段にタブ作成・更新を独立ボタンとして配置する。
- プル更新を廃止し、更新導線を下段更新ボタンに一本化する。
- 下部操作群とリスト終端が重ならないよう、スクロール末尾余白を保証する。

**Non-Goals:**
- タブ一覧以外（板画面本体、スレッド画面本体）のレイアウト刷新。
- タブデータモデルの永続仕様変更や遷移ルーティング契約の変更。
- タブ一覧外の更新仕様（他画面での pull-to-refresh）変更。

## Decisions

- 一覧表示は `OpenBoardsList` / `OpenThreadsList` の両方で「カード + 上段メタ情報 + 下段タイトル/補助情報」の共通構造に寄せる。
  - 代替案: 既存の `ListItem` と行ベース構造を維持して見た目だけ調整する。
  - 不採用理由: 情報の並びと操作位置が根本的に揃わず、Issue の「カード状」「上部に情報と×」要件を満たしにくい。

- 板/スレ切替は上部 `TabRow` から下部操作群の上段へ移動し、ページ切替操作を一覧末尾付近でも届く位置に固定する。
  - 代替案: `TabRow` を上部のまま維持し、下部には新規/更新のみ追加する。
  - 不採用理由: 操作導線が上下に分散したままで、要件の「下部に集約した2段構成」を満たさない。

- 下段操作は「左: タブ作成」「右: 更新」の独立アイコンボタンとし、板ページ選択時は更新ボタンを非表示にする。
  - 代替案: 1つの複合FABに統合する。
  - 不採用理由: 独立ボタン要件に反し、視認性と押し分け性が低下する。

- スレッド新着表示は板画面と同様に、強調色背景の丸バッジで差分数を表示する。
  - 代替案: 既存の `+n` テキスト表示を色のみ調整して継続する。
  - 不採用理由: 要件が「板画面と同じもの」を明示しており、視覚的一貫性も不足する。

- スレッド一覧の `PullToRefreshBox` は除去し、更新処理は下段更新ボタンからのみ呼び出す。
  - 代替案: 下段更新を追加しつつプル更新も併存させる。
  - 不採用理由: 要件でプル更新廃止が明示され、二重導線は操作モデルを複雑化させる。

- リスト下部には下部2段操作群の実高さ + マージン分の `contentPadding` を確保する。
  - 代替案: 画面全体 `padding(bottom = ...)` のみで吸収する。
  - 不採用理由: ボトムシート内のスクロール終端で重なりが発生しやすく、要件を保証しづらい。

## Risks / Trade-offs

- [リスク] ボトムシート高や端末サイズ差で下部操作群の占有率が変わり、余白不足が再発する。 → [緩和策] 一覧の `contentPadding` を固定値ではなく操作群レイアウトに連動した値で設計し、最小高さ端末で確認する。
- [リスク] 板ページ時の更新ボタン非表示条件を誤ると、スレページでも更新が消える。 → [緩和策] ページ選択状態を単一ソース（Pager state）で判定し、表示条件を一元化する。
- [トレードオフ] 既存FAB導線を廃止して下段ボタンへ寄せるため、初期学習コストが発生する。 → [緩和策] アイコンと配置を安定化し、常時表示で探索コストを下げる。
