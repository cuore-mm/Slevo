## ADDED Requirements

### Requirement: スレッド客観状態の共通永続化
システムはスレッドごとの最新レス数、タイトル、板情報、板内 thread key を、板画面・タブ一覧・スレッド画面から共通に参照できる永続状態として管理しなければならないMUST。共通状態は同一 `threadId` につき 1 件を正本とし、タブを閉じても保持されなければならないMUST。

#### Scenario: 同一スレッドの客観状態を1件に統合する
- **WHEN** 同じ `threadId` のスレッドが板画面、タブ一覧、スレッド画面の複数箇所から参照される
- **THEN** システムは同一の共通スレッド状態から最新レス数、タイトル、板情報、板内 thread key を取得する

#### Scenario: 板一覧キャッシュと板内キーで照合する
- **WHEN** システムが板一覧キャッシュと共通客観状態を照合する
- **THEN** システムは共通客観状態の `boardId` と `threadKey` を、板一覧キャッシュの `boardId` と板内 `threadId` に対応させる

#### Scenario: タブを閉じてもスレッド状態を保持する
- **WHEN** ユーザーが開いているスレッドタブを閉じる
- **THEN** システムはタブ固有状態を削除し、共通スレッド状態の最新レス数とタイトルを保持する

### Requirement: 既読状態の履歴紐づけ
システムは最終既読レス番号、最初の新着レス番号、前回レス数を閲覧履歴に紐づく状態として管理しなければならないMUST。ユーザーがスレッド履歴を削除した場合、当該スレッドの既読状態も削除されなければならないMUST。

#### Scenario: 履歴削除で既読状態を削除する
- **WHEN** ユーザーがスレッド履歴を削除する
- **THEN** システムは当該スレッドの最終既読レス番号、最初の新着レス番号、前回レス数を削除する

#### Scenario: 開いているタブがある履歴を削除する
- **WHEN** ユーザーが開いているタブと同じ `threadId` のスレッド履歴を削除する
- **THEN** システムはタブを残したまま当該スレッドの既読状態を削除し、タブ表示では未訪問として扱う

#### Scenario: 履歴がないスレッドを未訪問として扱う
- **WHEN** スレッドの共通客観状態は存在するが閲覧履歴が存在しない
- **THEN** システムは当該スレッドを未訪問として扱い、新着レス数バッジを表示しない

### Requirement: 履歴レス数スナップショット
システムは閲覧履歴に保存するレス数を、履歴表示用スナップショットとして保持しなければならないMUST。最新レス数の正本は共通客観状態の `latestResCount` とし、新着レス数の計算に履歴レス数スナップショットを使用してはならないMUST NOT。

#### Scenario: 板更新では履歴レス数を更新しない
- **WHEN** 板更新によりスレッドの最新レス数が増加する
- **THEN** システムは共通客観状態の最新レス数を更新し、閲覧履歴のレス数スナップショットは更新しない

#### Scenario: スレッド閲覧で履歴レス数を更新する
- **WHEN** ユーザーがスレッドを閲覧し履歴が記録または更新される
- **THEN** システムは閲覧履歴のレス数スナップショットをその時点のレス数で更新する

### Requirement: 画面間の新着レス数同期
システムは板画面のスレ一覧とタブ一覧のスレ一覧で、同一スレッドの新着レス数を同じ共通客観状態、同じ履歴紐づき既読状態、同じ計算規則から導出しなければならないMUST。どちらかの画面でレス数または既読状態が更新された場合、もう一方の画面にも同じ新着レス数が反映されなければならないMUST。

#### Scenario: 板更新後にタブ一覧へ新着レス数を反映する
- **WHEN** 板画面のスレ一覧更新で、開いているスレッドの最新レス数が増加する
- **THEN** システムは共通客観状態を更新し、履歴が存在するタブ一覧の同一スレッドに同じ新着レス数を表示する

#### Scenario: タブ一覧更新後に板画面へ新着レス数を反映する
- **WHEN** タブ一覧のスレッド更新で、板画面にも表示されるスレッドの最新レス数が増加する
- **THEN** システムは共通客観状態を更新し、履歴が存在する板画面の同一スレッドに同じ新着レス数を表示する

#### Scenario: スレッド閲覧後に新着レス数をクリアする
- **WHEN** ユーザーがスレッド画面で新着レス範囲を既読位置まで閲覧する
- **THEN** システムは履歴紐づき既読状態の最終既読レス番号を更新し、板画面とタブ一覧の同一スレッドの新着レス数を同じ値に更新する

### Requirement: 更新経路の統一
システムは板更新、タブ一覧更新、スレッド閲覧・更新の各経路で共通客観状態を更新し、既読位置更新では履歴紐づき既読状態を更新しなければならないMUST。表示時には共通客観状態と履歴紐づき既読状態を整合した組み合わせとして合成しなければならないMUST。

#### Scenario: 板更新で最新レス数を保存する
- **WHEN** subject.txt の取得によりスレッドのレス数が判明する
- **THEN** システムは板一覧キャッシュを更新するとともに、対象スレッドの共通客観状態の最新レス数を更新する

#### Scenario: タブ一覧更新で最新レス数を保存する
- **WHEN** タブ一覧の更新処理により開いているスレッドのレス数が判明する
- **THEN** システムは対象スレッドの共通客観状態の最新レス数を更新し、タブ固有状態にはレス数の正本を保存しない

#### Scenario: 既読位置更新を保存する
- **WHEN** スレッド画面がユーザーの最終既読レス番号を更新する
- **THEN** システムは対象スレッドの履歴紐づき既読状態に最終既読レス番号と新着開始レス番号を保存する

### Requirement: 既存データの移行
システムは DB スキーマ変更時に、既存のタブ、履歴、板一覧キャッシュに保存されているスレッド情報から共通客観状態を生成しなければならないMUST。移行後も開いていたタブの並び順、スクロール位置、履歴に紐づく既読状態、最新レス数は可能な限り保持されなければならないMUST。

#### Scenario: タブ由来の状態を移行する
- **WHEN** 既存 DB に開いているスレッドタブが存在する状態でアプリが新スキーマへ移行する
- **THEN** システムはタブの `threadId`、レス数、タイトルから共通客観状態を作成し、タブの並び順とスクロール位置を保持する

#### Scenario: 履歴由来の状態を移行する
- **WHEN** 既存 DB に閲覧履歴が存在する状態でアプリが新スキーマへ移行する
- **THEN** システムは履歴の `threadId`、レス数、タイトルから共通客観状態を作成し、既読状態は履歴に紐づく状態として保持する

#### Scenario: 複数の移行元に同一スレッドが存在する
- **WHEN** 同じ `threadId` がタブ、履歴、板一覧キャッシュの複数箇所に存在する
- **THEN** システムは 1 件の共通客観状態へ統合し、最新レス数は利用可能な値のうち最大値を保持する

#### Scenario: 移行時に板内キーを保存する
- **WHEN** 既存のタブまたは履歴から共通客観状態を作成する
- **THEN** システムは `threadId` に含まれる板内 thread key を `threadKey` として保存する

### Requirement: タブ固有状態とスレッド状態の分離
システムは開いているスレッドタブの並び順とスクロール位置を、スレッドの客観状態および履歴紐づき既読状態とは分離して管理しなければならないMUST。タブ一覧の表示モデルは、タブ固有状態、共通客観状態、履歴紐づき既読状態を合成して生成されなければならないMUST。保存済みスクロール位置は履歴が存在する場合のみ有効として扱わなければならないMUST。

#### Scenario: タブ一覧表示モデルを合成する
- **WHEN** ユーザーがタブ一覧のスレッド一覧を表示する
- **THEN** システムはタブ固有状態から並び順とスクロール位置を取得し、共通客観状態からタイトルと最新レス数を取得し、履歴紐づき既読状態から新着レス数と既読状態を導出して表示する

#### Scenario: タブ保存でレス数の正本を更新しない
- **WHEN** システムが開いているスレッドタブの並び順またはスクロール位置を保存する
- **THEN** システムはタブ固有状態を保存し、最新レス数・既読状態の正本をタブ保存処理で上書きしない

#### Scenario: 履歴がないタブは先頭位置として表示する
- **WHEN** 開いているスレッドタブに保存済みスクロール位置があり、同じ `threadId` の閲覧履歴が存在しない
- **THEN** システムは表示モデルのスクロール位置を先頭位置として生成する

#### Scenario: 履歴があるタブは保存済みスクロール位置を使う
- **WHEN** 開いているスレッドタブに保存済みスクロール位置があり、同じ `threadId` の閲覧履歴が存在する
- **THEN** システムは表示モデルに保存済みスクロール位置を反映する

### Requirement: 共通客観状態の遅延GC
システムは共通客観状態を即時削除せず、参照がなくなった可能性のあるイベント後に遅延 GC として削除しなければならないMUST。削除対象は、参照がなく、かつ最終更新から 30 日以上経過した共通客観状態に限定しなければならないMUST。

#### Scenario: 参照がある状態はGCしない
- **WHEN** 共通客観状態がタブ、履歴、ブックマーク、または保持対象の板一覧キャッシュから参照されている
- **THEN** システムは当該共通客観状態を GC で削除しない

#### Scenario: 古い孤立状態をGCする
- **WHEN** 共通客観状態がどこからも参照されず、最終更新から 30 日以上経過している
- **THEN** システムはイベント後または起動時の GC で当該共通客観状態を削除対象にする

#### Scenario: 起動時GCは削除件数を制限する
- **WHEN** アプリ起動時に共通客観状態の GC を実行する
- **THEN** システムは 1 回の GC で処理する削除件数に上限を設ける
