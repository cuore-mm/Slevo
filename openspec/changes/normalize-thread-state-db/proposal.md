## Why

板画面のスレ一覧とタブ一覧のスレ一覧で、新着レス数・既読状態・最新レス数の算出元が分散しており、同じスレッドでも表示が同期しない可能性がある。DB 上のスレッド状態を正規化し、各画面が同じ永続状態を参照することで、更新経路に依存しない一貫した新着表示を実現する。

## What Changes

- スレッドごとの最新レス数・既読レス番号・新着開始レス番号を保持する共通のスレッド状態ストアを導入する。
- 板画面のスレ一覧とタブ一覧のスレ一覧は、共通のスレッド状態から新着レス数を算出して表示する。
- 板更新、タブ一覧更新、スレッド閲覧・更新の各経路で、同じスレッド状態を更新する。
- `open_thread_tabs` はタブとしての状態（並び順、スクロール位置など）を主に保持し、レス数・既読状態の正本として扱わない。
- 既存ユーザーの DB から、タブ・履歴・板キャッシュに分散したスレッド状態を共通ストアへ移行する。
- **BREAKING** Room DB のスキーマを変更し、マイグレーションとスキーマ検証の更新が必要になる。

## Capabilities

### New Capabilities
- `thread-state-sync`: スレッド状態を共通化し、板画面・タブ一覧・スレッド画面で新着レス数と既読状態を同期する仕様。

### Modified Capabilities
- `tablist-ui`: スレッドタブ一覧の新着レス数表示を、タブ固有の一時状態ではなく共通スレッド状態に基づく表示へ変更する。

## Impact

- 影響範囲: Room DB エンティティ・DAO・マイグレーション、Repository、板画面 ViewModel/Coordinator、タブ一覧 Coordinator、スレッド画面の既読更新経路。
- データ移行: `open_thread_tabs`、`thread_histories`、`thread_summaries` に存在するレス数・既読状態から共通スレッド状態を生成する。
- テスト: マイグレーションテスト、スレッド状態統合ロジックの単体テスト、板画面とタブ一覧の新着表示同期の単体または UI 状態テストを追加・更新する。
