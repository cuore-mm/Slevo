## Why

板画面のスレ一覧とタブ一覧のスレ一覧で、新着レス数・既読状態・最新レス数の算出元が分散しており、同じスレッドでも表示が同期しない可能性がある。DB 上の客観状態と閲覧履歴に紐づく既読状態を整理し、各画面が同じ組み合わせから表示値を導出することで、更新経路に依存しない一貫した新着表示を実現する。

## What Changes

- スレッドごとの最新レス数・タイトル・板情報を保持する共通の `thread_states` を導入する。
- 既読レス番号・新着開始レス番号・前回レス数は閲覧履歴に紐づく状態として扱い、履歴削除時に削除されるようにする。
- 板画面のスレ一覧とタブ一覧のスレ一覧は、`thread_states` と `thread_histories` の同じ組み合わせから新着レス数を算出して表示する。
- 板更新、タブ一覧更新、スレッド閲覧・更新の各経路で、最新レス数は `thread_states`、既読位置は `thread_histories` を更新する。
- `open_thread_tabs` はタブとしての状態（並び順、スクロール位置など）を主に保持し、レス数・既読状態の正本として扱わない。
- 既存ユーザーの DB から、タブ・履歴・板キャッシュに分散した最新レス数とタイトルを `thread_states` へ移行し、既読状態は履歴側に保持する。
- **BREAKING** Room DB のスキーマを変更し、マイグレーションとスキーマ検証の更新が必要になる。

## Capabilities

### New Capabilities
- `thread-state-sync`: スレッドの客観状態を共通化し、履歴に紐づく既読状態と組み合わせて板画面・タブ一覧・スレッド画面の新着レス数を同期する仕様。

### Modified Capabilities
- `tablist-ui`: スレッドタブ一覧の新着レス数表示を、タブ固有の一時状態ではなく `thread_states` と履歴紐づき既読状態に基づく表示へ変更する。

## Impact

- 影響範囲: Room DB エンティティ・DAO・マイグレーション、Repository、板画面 ViewModel/Coordinator、タブ一覧 Coordinator、スレッド画面の既読更新経路。
- データ移行: `open_thread_tabs`、`thread_histories`、`thread_summaries` に存在するレス数・タイトルから `thread_states` を生成し、既読状態は `thread_histories` に残す。
- テスト: マイグレーションテスト、スレッド状態統合ロジックの単体テスト、板画面とタブ一覧の新着表示同期の単体または UI 状態テストを追加・更新する。
