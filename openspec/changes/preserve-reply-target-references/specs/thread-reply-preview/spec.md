# Spec Delta

## MODIFIED Requirements

### Requirement: 安価だけの行から返信先を一件選ぶ
システムは行の前後空白を除く全内容が有効な安価または空白区切りの複数安価である各行に、最大一件の返信先表示を挿入しなければならない（SHALL）。取得済み候補は行内の出現順、範囲内の昇順で重複を除き、正常な取得済みレス、NGの取得済みレスの順に優先して選ばなければならない（SHALL）。同じ種別内では最初の候補を選び、文中安価の行には挿入してはならない（MUST NOT）。取得済みレス数を超える番号は候補へ個別展開せず、未取得範囲としてまとめなければならない（SHALL）。

#### Scenario: 空白付き安価と複数安価の行
- **WHEN** 行が` >>1 `または`>>1 >>3`である
- **THEN** その行に候補の状態に応じた返信先を最大一件表示する

#### Scenario: 文中安価を候補にしない
- **WHEN** 本文が`>>1 ありがとう`、改行、`>>2`であり、両参照先が表示可能である
- **THEN** 1の行には挿入せず、2の行に2のプレビューを表示する

#### Scenario: 最初の表示可能な候補まで進む
- **WHEN** 本文に`>>1,3`、改行、`>>4`があり、1がNGで3と4が正常である
- **THEN** 最初の行には3のプレビューと「ほか1件」、次の行には4のプレビューを表示する
- **AND** 最初の行の一覧では1もNG状態として確認できる

#### Scenario: 取得済み候補と未取得範囲を表示する
- **WHEN** 100件取得済みのスレッドで対象行が`>>90-200`である
- **THEN** 90のプレビューと「ほか10件」を表示する
- **AND** 「ほか10件」の直下に「101〜200は未取得です」と表示する
- **AND** 101から200を番号ごとの候補として生成しない

#### Scenario: 取得済み候補がなく未取得範囲だけである
- **WHEN** 100件取得済みのスレッドで対象行が`>>101-2147483647`である
- **THEN** 番号を個別表示せず「101〜2147483647は未取得です」と表示する
- **AND** 返信先候補の展開に固定件数上限を必要としない

#### Scenario: 本文内の各安価行を置換する
- **WHEN** 本文が`>>1`、本文1、`>>2`、本文2の順であり、1と2が正常である
- **THEN** 1のプレビュー、本文1、2のプレビュー、本文2の順で表示する

### Requirement: 安価行と返信先プレビューのまとまり
システムは単一・範囲・カンマ・空白区切りの対象安価行を、その位置の返信先カードまたは状態表示に置換しなければならない（SHALL）。元の安価行を別途重複描画してはならない（MUST NOT）。取得済み参照番号と未取得範囲を保持し、前後の通常本文の順序・改行とリンク操作を維持しなければならない（SHALL）。未取得範囲を扱うために範囲内の全番号を列挙してはならない（MUST NOT）。

#### Scenario: 単一安価を一体化する
- **WHEN** `>>1`だけの行に1のプレビューを表示する
- **THEN** 安価番号を枠の見出し部分としてプレビューと一体化し、同じ安価行を別途重複描画しない

#### Scenario: 複数形式も元行を置換する
- **WHEN** `>>1-5`、`>>1,3`または`>>1 >>3`の行に返信先を表示する
- **THEN** 元行を描画せず、その位置に一件の返信先と必要な「ほかN件」を表示する

#### Scenario: 本文途中のリンクを維持する
- **WHEN** 二つの対象安価行の前後にURLと文中安価がある
- **THEN** 前後の本文順序、URL・文中安価のタップ先、通常本文の長押し操作を維持する

### Requirement: 返信元の選択と省略分の表示
システムは当該レスの本文・通常画像の下に、NG除外済み返信元をレス番号昇順で最大三件表示しなければならない（SHALL）。返信元の残数はNG除外後の候補数から三件までの表示数を引き、返信先の残数は行内の取得済み候補数から表示一件を引いて「ほかN件」としなければならない（SHALL）。返信先の残数からNGを除外してはならず、未取得範囲はこの件数に含めず別に範囲表示しなければならない（SHALL）。省略操作は取得済み候補と未取得範囲を含む返信先一覧を開かなければならない（SHALL）。返信元群は見出し・囲み枠・塗りつぶし背景を使わず、左縦線と項目間の区切り線で表示し、その省略操作も背景なしとし、返信先の囲みカード外観は維持しなければならない（SHALL）。

#### Scenario: 返信元を見出しなしの引用風表示にする
- **WHEN** 返信元プレビューを一件以上表示する
- **THEN** 「返信」または返信件数の見出しを表示せず、各項目を左の縦線と項目間の区切り線で分け、外側の囲み枠・塗りつぶし背景なしで表示する
- **AND** 各項目のヘッダーはレス番号の数字から始め、「レス」や`>>`を前置しない

#### Scenario: 返信元の省略操作を背景なしで表示する
- **WHEN** 表示上限を超える返信元があり「ほかN件」を表示する
- **THEN** 省略操作は塗りつぶし背景なしで表示し、全返信元を開く操作性を維持する

#### Scenario: 返信先カード外観を維持する
- **WHEN** 返信先プレビューを表示する
- **THEN** 返信元専用の引用風外観を適用せず、従来の囲みカードとして表示する

#### Scenario: 返信元が五件ある
- **WHEN** NGでない返信元が2、4、6、8、10である
- **THEN** 2、4、6のプレビューと「ほか2件」を表示し、省略表示のタップで五件すべてを確認できる

#### Scenario: 返信先が複数行にある
- **WHEN** 安価だけの行の参照先が順に1、3、1、5であり、すべて正常である
- **THEN** 各行に1、3、1、5のプレビューを表示し、別行の同じ番号を理由に表示を省かない

#### Scenario: 正常三件とNG二件
- **WHEN** 一つの安価行の候補が正常3件とNG2件である
- **THEN** 正常1件のプレビューと「ほか4件」を表示し、一覧は正常3件とNG2件すべてを含む

#### Scenario: 正常一件とNG四件
- **WHEN** 一つの安価行の候補が正常1件とNG4件である
- **THEN** 正常1件のプレビューと「ほか4件」を表示し、残り四件はすべてNG状態として確認できる

#### Scenario: NG三件
- **WHEN** 一つの安価行の候補がNG3件である
- **THEN** 最初のNGの番号・非表示状態・表示ボタンと「ほか2件」を表示する

#### Scenario: NG二件と未取得一件
- **WHEN** 100件取得済みのスレッドで一つの安価行が`>>1-2 >>105`であり、1と2がNGである
- **THEN** 最初のNGの番号・非表示状態・表示ボタンと「ほか1件」を表示する
- **AND** 「ほか1件」の下に「105は未取得です」と表示する

#### Scenario: 未取得三件
- **WHEN** 100件取得済みのスレッドで一つの安価行が`>>101-103`である
- **THEN** 個別の未取得候補や「ほかN件」を表示せず「101〜103は未取得です」とまとめて表示する

#### Scenario: 取得済み候補と未取得範囲の件数を分ける
- **WHEN** 100件取得済みのスレッドで一つの安価行が`>>98-102`である
- **THEN** 98のプレビュー、「ほか2件」、その直下に「101〜102は未取得です」を表示する

## ADDED Requirements

### Requirement: 返信先の参照不能状態と一時開示
システムはNGの取得済み返信先を番号・「NGで非表示」・「表示」ボタンで表示し、未取得番号は統合した番号範囲と未取得状態の文言で表示しなければならない（SHALL）。NGの「表示」はそのプレビュー内で通常のプレビュー形式へ切り替え「隠す」を表示し、「隠す」は非表示状態へ戻さなければならない（SHALL）。NG設定と他の表示箇所を変更してはならない（MUST NOT）。非表示中の本文・画像を描画・読み上げ・先行読込してはならない（MUST NOT）。

#### Scenario: プレビュー内で表示して隠す
- **WHEN** NG返信先の「表示」を押してから「隠す」を押す
- **THEN** 同じ位置で最大三行本文のプレビューと隠すボタンを表示した後、番号とNG非表示状態へ戻る
- **AND** 別のプレビューとポップアップの同番号の開示状態、NG設定は変わらない

#### Scenario: 状態表示のアクセシビリティ
- **WHEN** 読み上げやキーボードでNG・未取得の返信先を操作する
- **THEN** 対象番号、状態、表示と隠すの操作を区別でき、非表示の本文は読み上げられず、ボタンは48dp以上の操作領域を持つ

#### Scenario: 追加取得とNG更新
- **WHEN** 未取得の候補を追加取得する、または候補のNG状態が変わる
- **THEN** 取得済み候補と未取得範囲を再分類して表示と残数を更新し、新たにNGとなったレスは明示操作まで非表示とする

### Requirement: 未取得番号範囲の有限な表現
システムは返信先候補に固定件数上限を設けず、取得済み候補のみをレス数の範囲内で列挙し、取得済みレス数を超える参照を未取得範囲として保持しなければならない（SHALL）。未取得範囲は重複・隣接区間を統合して有限個の範囲状態として表示し、「ほかN件」には含めてはならない（SHALL）。巨大範囲の番号を全列挙してはならない（MUST NOT）。

#### Scenario: 巨大範囲を取得済みレスと分離する
- **WHEN** 100件取得済みのスレッドで行が`>>1-2147483647`である
- **THEN** 取得済み候補1から100だけを扱う
- **AND** 未取得範囲101〜2147483647をまとめて表示する
- **AND** 範囲全体を列挙せず応答する

#### Scenario: 複数の未取得範囲を重複除去する
- **WHEN** 100件取得済みのスレッドで行が`>>105-110 >>108-120 >>130`である
- **THEN** 重複区間を統合した「105〜120、130は未取得です」と表示する

#### Scenario: 取得済み候補の重複を除く
- **WHEN** 行が`>>1-100 >>1-100`であり100件取得済みである
- **THEN** 取得済み候補を1から100まで一度ずつだけ扱う

#### Scenario: 未取得範囲を返信先一覧にも集約する
- **WHEN** 100件取得済みのスレッドで`>>90-200`の返信先一覧を開く
- **THEN** 取得済み候補90から100を元の順で表示し、101〜200を一つの未取得範囲行として表示する
