# Spec Delta

## MODIFIED Requirements

### Requirement: 安価だけの行から返信先を一件選ぶ
システムは行の前後空白を除く全内容が有効な安価または空白区切りの複数安価である各行に、最大一件の返信先表示を挿入しなければならない（SHALL）。候補は行内の出現順、範囲内の昇順で重複を除き、正常な取得済みレス、NGの取得済みレス、未取得の順に優先して選ばなければならない（SHALL）。同じ種別内では最初の候補を選び、文中安価の行には挿入してはならない（MUST NOT）。

#### Scenario: 空白付き安価と複数安価の行
- **WHEN** 行が` >>1 `または`>>1 >>3`である
- **THEN** その行に候補の状態に応じた返信先を最大一件表示する

#### Scenario: 文中安価を候補にしない
- **WHEN** 本文が`>>1 ありがとう`、改行、`>>2`であり、両参照先が表示可能である
- **THEN** 1の行には挿入せず、2の行に2のプレビューを表示する

#### Scenario: 最初の表示可能な候補まで進む
- **WHEN** 本文に`>>1,3`、改行、`>>4`があり、1がNGで3と4が正常である
- **THEN** 最初の行には3のプレビューと「ほか1件」、次の行には4のプレビューを表示する
- **AND** 最初の行の一覧では1もNG状態として確認できる

#### Scenario: 表示可能な参照先がない
- **WHEN** 対象行の候補がNGと未取得だけである
- **THEN** NGが一件以上なら最初のNGの非表示状態、全件未取得なら最初の未取得状態を表示する
- **AND** 残る候補は状態を問わず「ほかN件」に数える

#### Scenario: 本文内の各安価行を置換する
- **WHEN** 本文が`>>1`、本文1、`>>2`、本文2の順であり、1と2が正常である
- **THEN** 1のプレビュー、本文1、2のプレビュー、本文2の順で表示する

### Requirement: 安価行と返信先プレビューのまとまり
システムは単一・範囲・カンマ・空白区切りの対象安価行を、その位置の返信先カードまたは状態表示に置換しなければならない（SHALL）。元の安価行を別途重複描画してはならない（MUST NOT）。参照番号の情報は上限内の候補一覧で保持し、前後の通常本文の順序・改行とリンク操作を維持しなければならない（SHALL）。

#### Scenario: 単一安価を一体化する
- **WHEN** `>>1`だけの行に1のプレビューを表示する
- **THEN** 安価番号を枠の見出し部分としてプレビューと一体化し、同じ安価行を別途重複描画しない

#### Scenario: 複数形式も元行を置換する
- **WHEN** `>>1-5`、`>>1,3`または`>>1 >>3`の行に返信先を表示する
- **THEN** 元行を描画せず、その位置に一件の返信先と必要な「ほかN件」を表示する

#### Scenario: 本文途中のリンクを維持する
- **WHEN** 二つの対象安価行の前後にURLと文中安価がある
- **THEN** 前後の本文順序、URL・文中安価のタップ先、通常本文の長押し操作を維持する

### Requirement: 返信元の選択と省略分の表示
システムは当該レスの本文・通常画像の下に、NG除外済み返信元をレス番号昇順で最大三件表示しなければならない（SHALL）。返信元の残数はNG除外後の候補数から三件までの表示数を引き、返信先の残数は行ごとの上限内候補数から表示一件を引いて「ほかN件」としなければならない（SHALL）。返信先の残数からNG・未取得を除外してはならない（MUST NOT）。省略操作は対応する候補全件の一覧を開かなければならない（SHALL）。返信元群は見出し・囲み枠・塗りつぶし背景を使わず、左縦線と項目間の区切り線で表示し、その省略操作も背景なしとし、返信先の囲みカード外観は維持しなければならない（SHALL）。

#### Scenario: 返信元を見出しなしの引用風表示にする
- **WHEN** 返信元プレビューを一件以上表示する
- **THEN** 「返信」または返信件数の見出しを表示せず、各項目を左の縦線と項目間の区切り線で分け、外側の囲み枠・塗りつぶし背景なしで表示する
- **AND** 各項目のヘッダーはレス番号の数字から始め、「レス」や`>>`を前置しない

#### Scenario: 返信元の省略操作を背景なしで表示する
- **WHEN** 表示上限を超える返信元があり「ほかN件」を表示する
- **THEN** 省略操作は塗りつぶし背景なしで表示し、全返信元を開く操作性を維持する

#### Scenario: 返信先カード外観を維持する
- **WHEN** 返信先プレビューを表示する
- **THEN** 返信元専用の引用風外観を適用せず、従来の囲みカードとして表示する

#### Scenario: 返信元が五件ある
- **WHEN** NGでない返信元が2、4、6、8、10である
- **THEN** 2、4、6のプレビューと「ほか2件」を表示し、省略表示のタップで五件すべてを確認できる

#### Scenario: 返信先が複数行にある
- **WHEN** 安価だけの行の参照先が順に1、3、1、5であり、すべて正常である
- **THEN** 各行に1、3、1、5のプレビューを表示し、別行の同じ番号を理由に表示を省かない

#### Scenario: 正常三件とNG二件
- **WHEN** 一つの安価行の候補が正常3件とNG2件である
- **THEN** 正常1件のプレビューと「ほか4件」を表示し、一覧は正常3件とNG2件すべてを含む

#### Scenario: 正常一件とNG四件
- **WHEN** 一つの安価行の候補が正常1件とNG4件である
- **THEN** 正常1件のプレビューと「ほか4件」を表示し、残り四件はすべてNG状態として確認できる

#### Scenario: NG三件
- **WHEN** 一つの安価行の候補がNG3件である
- **THEN** 最初のNGの番号・非表示状態・表示ボタンと「ほか2件」を表示する

#### Scenario: NG二件と未取得一件
- **WHEN** 一つの安価行の候補がNG2件と未取得1件である
- **THEN** 最初のNGの番号・非表示状態・表示ボタンと「ほか2件」を表示し、残りはNG1件と未取得1件とする

#### Scenario: 未取得三件
- **WHEN** 一つの安価行の候補が未取得3件である
- **THEN** 最初の未取得番号の状態表示と「ほか2件」を表示する

## ADDED Requirements

### Requirement: 返信先の参照不能状態と一時開示
システムはNGの返信先を番号・「NGで非表示」・「表示」ボタン、未取得の返信先を番号・「未取得のため参照できません」で表示しなければならない（SHALL）。NGの「表示」はそのプレビュー内で通常のプレビュー形式へ切り替え「隠す」を表示し、「隠す」は非表示状態へ戻さなければならない（SHALL）。NG設定と他の表示箇所を変更してはならない（MUST NOT）。非表示中の本文・画像を描画・読み上げ・先行読込してはならない（MUST NOT）。

#### Scenario: プレビュー内で表示して隠す
- **WHEN** NG返信先の「表示」を押してから「隠す」を押す
- **THEN** 同じ位置で最大三行本文のプレビューと隠すボタンを表示した後、番号とNG非表示状態へ戻る
- **AND** 別のプレビューとポップアップの同番号の開示状態、NG設定は変わらない

#### Scenario: 状態表示のアクセシビリティ
- **WHEN** 読み上げやキーボードでNG・未取得の返信先を操作する
- **THEN** 対象番号、状態、表示と隠すの操作を区別でき、非表示の本文は読み上げられず、ボタンは48dp以上の操作領域を持つ

#### Scenario: 追加取得とNG更新
- **WHEN** 未取得の候補を追加取得する、または候補のNG状態が変わる
- **THEN** 行ごとの候補数と番号を維持して状態と優先表示を更新し、新たにNGとなったレスは明示操作まで非表示とする

### Requirement: 返信先候補の千件上限と超過通知
システムは安価行ごとに出現順で重複を除いた最初の1,000件だけを候補に保持しなければならない（SHALL）。正常優先の選択は保持した候補内で行い、「ほかN件」は保持数から一件を引かなければならない（SHALL）。1,001件目の異なる候補がある場合に限り「ほかN件」の直下と候補一覧末尾に「参照先が上限を超えたため、一部を省略しています」と表示しなければならない（SHALL）。巨大範囲や重複範囲の全列挙を行ってはならない（MUST NOT）。

#### Scenario: ちょうど千件
- **WHEN** 行が`>>1-1000`である
- **THEN** 候補1,000件と「ほか999件」を扱い、超過通知を出さない

#### Scenario: 上限を超える
- **WHEN** 行が`>>1-2147483647`である
- **THEN** 1から1,000だけを保持し「ほか999件」と両箇所の超過通知を表示して、全範囲を列挙せず応答する

#### Scenario: 重複を数えない
- **WHEN** 行が`>>1-1000 >>1-1000`である
- **THEN** 候補は1,000件で、重複を上限超過とみなさない

#### Scenario: 後続行は別に処理する
- **WHEN** 一行目が上限超過で二行目にも有効な安価行がある
- **THEN** 一行目の打切りに関係なく二行目の候補と返信先表示を生成する
