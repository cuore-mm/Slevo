# Spec Delta

## MODIFIED Requirements

### Requirement: スレッド更新後のレスポップアップ安定表示
システムはレスポップアップの表示対象を投稿UIモデルの等価性ではなくスレッド内の投稿番号で管理し、更新後も最新の投稿を番号から解決しなければならない（MUST）。返信先候補一覧では取得済みの正常・NG候補だけを表示し、取得済み投稿がない候補を一覧に表示してはならない（MUST NOT）。その他の一覧では従来の対象選別を維持しなければならない（MUST）。古い投稿モデルの照合失敗、負の添字、範囲外アクセスによってクラッシュしてはならない（MUST NOT）。

#### Scenario: ポップアップ表示中にスレッドが更新される
- **WHEN** ユーザーがレスポップアップを表示している状態でスレッド更新により投稿一覧と派生情報が再生成される
- **THEN** ポップアップが保持する投稿番号から最新の投稿を解決して表示を継続する
- **AND** 古い投稿UIモデルを最新投稿一覧へ等価照合する前提に依存しない

#### Scenario: 最新投稿一覧に対象投稿番号が存在しない
- **WHEN** 更新後の投稿数が減り、返信先ポップアップが保持する番号の一部を解決できない
- **THEN** 解決不能な番号を返信先一覧から除外し、未取得範囲の状態行を表示しない
- **AND** 解決可能な候補が一件も残らない場合は返信先一覧を閉じる
- **AND** 投稿一覧や派生情報へ範囲外添字でアクセスしない

#### Scenario: ID順序派生情報が投稿一覧と一時的に不整合になる
- **WHEN** ポップアップ描画時に投稿番号から算出した添字がID順序情報の範囲外になる
- **THEN** 安全な既定値でID順序表示を継続し、範囲外例外を発生させない

## ADDED Requirements

### Requirement: 返信先候補を既存投稿表示内で開示
返信先候補一覧は選択済みを含む取得済み候補だけを元の出現順で表示し、取得済み候補がない場合は開かず、更新後に候補が全て解決不能となれば閉じなければならない（SHALL）。

#### Scenario: 全件NGでも取得済み候補一覧を維持する
- **WHEN** 取得済み候補がNG2件である返信先一覧を開く
- **THEN** 二つのNG状態を表示し、通常レスがゼロでも一覧を閉じない

#### Scenario: 一覧から未取得範囲を除外する
- **WHEN** 100件取得済みのスレッドで`90-200`を参照する行の「ほか10件」から返信先一覧を開く
- **THEN** 一覧には90から100の取得済み候補だけを表示する
- **AND** 101から200の未取得範囲行を表示しない

#### Scenario: 未取得範囲だけでは一覧を開かない
- **WHEN** 100件取得済みのスレッドで返信先候補が`101-200`だけである
- **THEN** 返信先一覧を開かず、インラインプレビューにだけ未取得範囲を表示する

### Requirement: 返信先ポップアップでNGレスを既存投稿形式のまま開示する
NG非表示時は番号・状態・「表示」だけを表示し、投稿情報・本文・画像を構成してはならない（MUST NOT）。開示中は既存`PostItem`のヘッダーと本文を使い、右端に「隠す」だけを追加しなければならない（SHALL）。開示状態の共有はNG設定を変更せず、新しいカード面タップを追加してはならない（MUST NOT）。

#### Scenario: NGレスを既存の通常投稿形式で開示する
- **WHEN** 返信先一覧内のNGレスの「表示」を押す
- **THEN** 新しいポップアップを開かず、既存`PostItem`の番号・名前・日時・IDの同じヘッダー行と通常本文を表示し、右端に「隠す」だけを追加する
- **AND** 通常レスと開示中NGレスで投稿情報の位置・書式は同じで、操作ボタン以外の独自表示を追加しない
- **AND** 「表示／隠す」ボタンに細い枠線を表示する
- **AND** 「隠す」を押すとNG非表示の番号・状態・「表示」へ戻る
- **AND** カード面への新しいタップ動作を追加しない

#### Scenario: NG更新で本文を漏らさない
- **WHEN** 一覧表示中の正常レスが新たにNGになる
- **THEN** 同じ番号の非表示状態行へ切り替え、明示的な表示操作まで本文と画像を表示しない

### Requirement: 開示状態を同一スレッドの表示箇所間で共有する
同一スレッド内の同一レス番号に対する開示状態は全ての返信先表示箇所で共有し、NGルール更新時にはクリアしなければならない（SHALL）。スレッドをまたいで共有してはならない（MUST NOT）。

#### Scenario: 開示状態を同一スレッドの表示箇所間で共有する
- **WHEN** 同番号がメインのプレビューと二つのポップアップにあり、一つの箇所でNGレスを開示する
- **THEN** メインのプレビューと両方のポップアップでその番号を開示状態にする
- **AND** いずれかの箇所で「隠す」を押すと、同一スレッド内の同番号を全て非表示状態に戻す
- **AND** ポップアップを閉じて開き直しても開示状態を保ち、別スレッドの同番号とNG設定には影響しない

#### Scenario: 非表示時の読み上げと画像読込
- **WHEN** 一覧に非表示のNGレスが含まれる
- **THEN** 本文・名前・ID・画像の内容を読み上げず画像を読み込まない
- **AND** 番号、NG状態、表示ボタンを読み上げとキーボードで識別でき、操作領域は48dp以上とする

#### Scenario: 返信先一覧から未取得範囲を除外する
- **WHEN** 返信先一覧の元の安価に取得済み候補と未取得範囲が含まれる
- **THEN** 一覧に取得済み候補だけを表示し、未取得範囲の状態行を表示しない
