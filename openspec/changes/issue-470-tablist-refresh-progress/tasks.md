## 2. キャンセル可能なスレッドタブ更新処理

- [ ] 2.1 `ThreadTabsCoordinator` で実行中の更新 `Job` を単一管理し、二重開始を防止する
- [ ] 2.2 更新開始時のスレッドタブ一覧をスナップショットとして保持し、対象タブ数を進捗総数へ反映する
- [ ] 2.3 各スレッド取得後に対象タブの `resCount` を更新し、`ThreadStateRepository.saveThreadState` で逐次保存する
- [ ] 2.4 取得失敗時は表示状態を維持しつつ、対象タブの処理完了として進捗を進める
- [ ] 2.5 キャンセル API を追加し、未処理タブの更新を中断して部分更新結果を保持する
- [ ] 2.6 更新中に削除済みのタブへ結果を反映しないよう、反映時に現在のタブ存在確認を行う
