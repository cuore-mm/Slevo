## Context

板画面とスレッド画面のボトムツールバーは、共通ユーティリティでスクロール追従を制御しているが、現状は「最下部到達時に再表示して固定する」独自ロジックを追加している。
このため、下方向スクロールで縮退した直後でも最下部到達で再展開され、スクロール方向に対する表示ルールが分かりづらい。要件は、初期表示は全表示を維持しつつ、下方向で縮退・上方向で展開・最下部到達では何もしない挙動への単純化である。

## Goals / Non-Goals

**Goals:**
- 板画面とスレッド画面で、同一のスクロール方向ベース挙動（下で縮退、上で展開）を適用する。
- 最下部到達時の自動再表示ロジックを撤廃し、挙動トリガーをスクロール方向のみに限定する。
- 画面初期表示時は従来どおりツールバー全体を表示し、既存UI構造（タイトル行 + ボタン行）は維持する。

**Non-Goals:**
- ツールバー内アクションの並び順や機能変更。
- 板/スレ以外の画面（履歴・ブックマーク等）のボトムバー挙動変更。
- スクロールジェスチャーや最下部更新（Bottom Pull to Refresh）仕様の変更。

## Decisions

- **最下部スティッキー制御を削除し、Material3標準の exitAlways を採用する**
  - 独自の末尾判定・保持タイマー・sticky フラグを廃止し、`BottomAppBarDefaults.exitAlwaysScrollBehavior` による自然な縮退/展開に一本化する。
  - 代替案として最下部判定を残したまま条件を緩和する方法もあるが、要件「最下部到達では何もしない」と矛盾しやすいため採用しない。

- **縮退見た目は既存 `FlexibleBottomAppBar` の構造に委ねる**
  - タイトル行とボタン行の分離済みレイアウトを維持し、下スクロール時にボタン群が隠れてタイトルのみ残る既存表現を継続利用する。
  - 代替案としてカスタムアニメーションを追加する方法は、仕様単純化の目的に対して過剰なため採用しない。

- **適用範囲は BoardScaffold / ThreadScaffold の共通経路に限定する**
  - 両画面は同一の `bottomBarScrollBehavior` 注入経路を通るため、ユーティリティ差し替えのみで一貫挙動を担保する。
  - 代替案として各画面で個別実装する方法は、将来的な挙動差分の温床になるため採用しない。

## Risks / Trade-offs

- [Risk] 既存の「最下部到達で操作ボタンを再表示する」前提で利用していたユーザーには挙動変更として認識される可能性がある。
  - Mitigation: 変更を仕様として明示し、スクロール方向のみで表示制御される一貫性を優先する。

- [Trade-off] 最下部到達で自動再表示しないため、最下部で直ちに操作したい場合は上方向へ軽くスクロールする必要がある。
  - Mitigation: 上方向スクロール時の展開レスポンスを維持し、復帰操作コストを最小化する。
