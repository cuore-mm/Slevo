## Context

`AnchoredOverlayMenu` はアンカー位置に重ねて表示する汎用メニューとして導入されたが、用途が増えたことで「重ねる」「隙間を空ける」「上下を自動で切り替える」といった意図を明示しづらくなっている。さらに `offset` の `y` が位置計算に反映されておらず、呼び出し側で縦方向の微調整ができない。

現在は `verticalSpacingPx` による gap 指定が `AnchoredTabActionMenu` で使われ、他の呼び出し元はデフォルト値に依存している。これにより、重ね表示の意図と非重なり表示の意図が混在し、維持が難しい状態になっている。

## Goals / Non-Goals

**Goals:**

- `AnchoredOverlayMenu` の縦位置指定を「重ね表示」「非重なり表示」「自動配置」で明示できるようにする。
- `offset.y` を含む縦方向の微調整が意図通りに効くようにする。
- 既存呼び出し元の表示意図（重ねる/離す）を明示的に維持する。

**Non-Goals:**

- メニューのアニメーションやデザイン、アイコン表示を変更すること。
- `Popup` の表示仕様そのものを変更すること。
- 画面外クランプの挙動を完全になくすこと。

## Decisions

### Decision: 縦位置の意図を明示できる enum を導入する

`Above` / `Below` / `Auto` に加えて、重ね表示用の `OverlapTop` / `OverlapBottom` を追加し、意図を明示する。

理由:

- 既存の `verticalSpacingPx` の符号だけでは意図が読み取りにくい。
- 重ね表示は UI 的に特殊なケースであり、呼び出し側で明示する方が安全。
- `Auto` は非重なり前提として扱いやすくなる。

代替案:

- `verticalSpacingPx` の符号だけで制御し続ける案は、既存と同様に意図が埋もれるため採用しない。

### Decision: `offset.y` を縦位置に必ず反映する

`offset` は水平/垂直の微調整に使える API として提供されているため、`offset.y` を縦位置計算に反映する。

理由:

- 現状の `offset.y` は無視されており API と実装が一致していない。
- `AnchoredSelectionMenu` などで縦位置の意図を表現するために必要。

### Decision: 既存呼び出し元は明示的な配置指定に更新する

`AnchoredSelectionMenu` は重ね表示、`AnchoredTabActionMenu` は非重なり表示、他のメニューは従来通りの表示意図を明示的に指定する。

理由:

- デフォルトの挙動に依存すると、将来的な API 変更時に意図が崩れる。
- 呼び出し側のコードから表示意図を読み取れるようにする。

## Risks / Trade-offs

- [Risk] 既存のメニュー位置が微妙に変わる → 主要な呼び出し元に対して明示指定し、差分を最小化する。
- [Risk] `offset.y` の反映で意図せず位置が変わる → 影響のある呼び出し元を洗い出し、意図に合わせた値へ調整する。
- [Risk] `Auto` が上下どちらを選ぶかで視覚的な一貫性が変わる → `Auto` は非重なり前提の利用箇所に限定する。

## Migration Plan

- `AnchoredOverlayMenu` の新しい縦位置指定を追加する。
- 既存の呼び出し元を、重ね表示か非重なり表示かに応じて明示的に更新する。
- `offset.y` の反映後に、主要画面でのメニュー位置を確認する。

## Open Questions

- デフォルト配置を `Below` に変更するかは、既存画面の影響範囲を確認してから決定する。
