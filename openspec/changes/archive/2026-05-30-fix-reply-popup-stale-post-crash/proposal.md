## Why

レスポップアップ表示中にスレッド更新が入ると、ポップアップが保持している古い投稿 UI モデルと最新の投稿一覧の照合に失敗し、`IndexOutOfBoundsException` でアプリがクラッシュする場合がある。ポップアップはスレッド更新後も継続表示されるため、表示対象を投稿オブジェクトではなく安定した投稿番号で管理し、最新状態から安全に解決する必要がある。

## What Changes

- レスポップアップの表示対象を、投稿 UI モデルのスナップショットではなく投稿番号のリストとして保持する。
- ポップアップ描画時は、保持した投稿番号から最新の `posts` と関連派生情報を解決して表示する。
- スレッド更新、NG 状態変更、範囲外投稿などで対象投稿を解決できない場合は、その投稿を安全にスキップまたはポップアップを空表示しない扱いにする。
- 返信番号、返信元、ID、ツリーポップアップ、多段ポップアップ、画像 shared transition の既存挙動を維持する。
- `idIndexList` など投稿一覧と同じ添字で参照する派生情報は、範囲外アクセスを起こさない防御的な取得に統一する。

## Capabilities

### New Capabilities
- なし

### Modified Capabilities
- `thread-tree-popup`: レスポップアップがスレッド更新後も安定した投稿番号で最新投稿を解決し、古い投稿モデル照合や範囲外アクセスでクラッシュしない要件を追加する。

## Impact

- 影響範囲: `PopupInfo`, `ReplyPopup`, `ThreadViewModel` のポップアップ作成処理、ポップアップ重複判定、ポップアップ内投稿描画。
- 既存 API/DB/ネットワーク契約の変更はない。
- Compose 表示ロジックと ViewModel の UI 状態構造が主な変更対象。
- 検証対象: レス番号ポップアップ、返信元ポップアップ、ID ポップアップ、ツリーポップアップ、多段ポップアップ、スレッド更新中のポップアップ再描画。
