## ADDED Requirements

### Requirement: 板更新キャッシュ差分の対象分離
システムは板更新時に、スレッド一覧キャッシュの存在判定とアーカイブ対象抽出を分離しなければならないMUST。存在判定はアーカイブ済み行を含む既存行を認識し、アーカイブ対象抽出は更新開始時点で未アーカイブの行だけを対象にしなければならないMUST。

#### Scenario: 現役スレッドが subject.txt から消えた
- **WHEN** 更新開始時点で未アーカイブのスレッドが最新 subject.txt に存在しない
- **THEN** システムは当該スレッドをアーカイブ対象に含める

#### Scenario: 既にアーカイブ済みのスレッドが subject.txt に存在しない
- **WHEN** 更新開始時点でアーカイブ済みのスレッドが最新 subject.txt に存在しない
- **THEN** システムは当該スレッドをアーカイブ対象に含めない

#### Scenario: アーカイブ済みスレッドが subject.txt に再出現する
- **WHEN** アーカイブ済みの既存スレッドが最新 subject.txt に存在する
- **THEN** システムは当該スレッドを新規挿入ではなく既存行更新として扱い、未アーカイブ状態へ戻す

### Requirement: 大量アーカイブ対象の安全な更新
システムは板更新時にアーカイブ対象スレッド ID が大量に存在しても、SQLite の SQL 変数上限を超えない単位でアーカイブ更新を実行しなければならないMUST。分割された更新は同じ板更新トランザクション内で扱われ、失敗時には板更新全体が不完全な状態で確定してはならないMUST NOT。

#### Scenario: アーカイブ対象が SQLite 変数上限を超える件数である
- **WHEN** 最新 subject.txt から消えた未アーカイブスレッド ID が 1 回の `IN` 句で扱える件数を超える
- **THEN** システムは複数回の安全な更新単位に分割して全対象をアーカイブする

#### Scenario: 分割更新中に失敗する
- **WHEN** アーカイブ対象の分割更新中に DB 更新エラーが発生する
- **THEN** システムは板更新トランザクションを確定せず、部分的なキャッシュ更新を残さない

### Requirement: 大量過去スレッド蓄積後の更新継続
システムは既存 DB にアーカイブ済み過去スレッドが大量に蓄積している板でも、最新 subject.txt に基づく板更新を完了しなければならないMUST。大量のアーカイブ済み行は、次回以降の板更新で繰り返しアーカイブ対象になってはならないMUST NOT。

#### Scenario: アーカイブ済み過去スレッドが大量に存在する板を更新する
- **WHEN** 対象板の `thread_summaries` に大量のアーカイブ済みスレッドが存在し、最新 subject.txt には現在の現役スレッドだけが含まれる
- **THEN** システムはアーカイブ済み過去スレッドを再更新対象にせず、現役スレッドの追加・更新・アーカイブを完了する

#### Scenario: 同じ板を再起動後に更新する
- **WHEN** アプリ再起動後に同じ板の更新を実行する
- **THEN** システムは過去のアーカイブ済み行の蓄積により `too many SQL variables` 相当の DB エラーを発生させずに更新を完了する
