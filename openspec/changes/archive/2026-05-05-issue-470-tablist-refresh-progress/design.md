## Context

タブ一覧画面は `TabsViewModel` が `TabsUiState` を公開し、板タブとスレッドタブの一覧・ロード状態・新着レス数をまとめて管理している。スレッドタブの更新処理は `ThreadTabsCoordinator.refreshOpenThreads()` に集約されているが、現在は更新中を Boolean で示すだけで、進捗、キャンセル、取得済みタブの逐次反映を扱っていない。

下部操作群は `TabListBottomControls` が描画し、板ページでは右端をプレースホルダーにしてスレッドページの更新ボタン位置を維持している。今回の変更は UI 表示、ViewModel 状態、コーディネータの更新処理にまたがるため、進捗状態の正本とキャンセル可能な更新ジョブを明確にする。

## Goals / Non-Goals

**Goals:**

- スレッドタブ一覧の更新中に、完了済み件数と総件数から算出した進捗を表示する。
- 更新中はスレッドページの更新ボタンをキャンセル操作へ切り替える。
- キャンセル時は実行中の更新ジョブを中断し、更新中状態と進捗状態を必ず解除する。
- 取得が完了したスレッドタブから順次レス数を保存し、既存の共通客観状態と履歴既読状態に基づいて新着レス数を反映する。
- 進捗状態は `TabsUiState` で共有し、タブ一覧内の板/スレページ切替では更新処理を継続する。

**Non-Goals:**

- DAT 取得 API、DB スキーマ、スレッド本文画面の更新仕様は変更しない。
- 板タブ一覧ページに更新ボタンを表示すること。
- スレッドごとの通信バイト進捗を統合した細粒度進捗は扱わず、開いているスレッドタブ単位の進捗を扱う。

## Decisions

### 1. 進捗はタブ件数ベースで表現する

`ThreadTabsCoordinator` に更新進捗用の状態を持たせ、`completed` と `total` から UI 表示用の割合を算出する。DAT 取得の `onProgress` を全タブ横断で合成する案もあるが、キャッシュ・Range・フォールバック取得で通信量の意味が揺らぐため、ユーザーに分かりやすい「更新済みタブ数 / 対象タブ数」を採用する。

### 2. 更新ジョブはコーディネータで単一管理する

`ThreadTabsCoordinator` に実行中の `Job` を保持し、更新開始、二重開始防止、キャンセル、完了時の状態クリアを同じ責務内で扱う。UI 側や `TabsViewModel` にジョブ管理を分散させる案もあるが、更新対象タブ、保存処理、既存の `isRefreshing` がすでにコーディネータにあるため、状態の正本を集約する。

### 3. 取得完了ごとに `ThreadStateRepository` へ保存する

全タブ取得後にまとめて保存する現在の方式では、途中経過を一覧へ反映できない。各タブ取得後に対象タブの `resCount` を更新し、同じタイミングで `saveThreadState` へ保存することで、既存の `TabsRepository.observeOpenThreadTabs()` と `ThreadNewResCalculator` による新着レス数再導出を活かす。

### 4. インジケーター領域は常時確保し、更新中は板/スレ両ページで描画する

`TabListBottomControls` のボタン Row の下に固定高さの進捗スロットを追加する。更新中は板/スレのどちらのページでも `LinearWavyProgressIndicator` を描画し、非更新時は空スロットにすることで、更新開始・終了や板/スレ切替で下部操作群の位置が変わらないようにする。

### 5. 板ページ切替時も更新処理は止めず、キャンセル操作を維持する

進捗状態とジョブは画面ページではなく `TabsViewModel` 配下のコーディネータに持たせる。これにより、ユーザーがタブ一覧内で板ページへ切り替えてもバックグラウンドでスレッドタブ更新を継続し、板ページでも進捗表示とキャンセル操作を維持できる。スレッドページへ戻った場合も同じ共有状態をそのまま表示する。

## Risks / Trade-offs

- [Risk] DAT 取得中のキャンセルが OkHttp の同期実行中に即時反映されない可能性がある → コルーチンキャンセルを伝播させ、少なくとも次の中断可能ポイントとループ継続前にキャンセル状態を確認する。
- [Risk] 更新中にタブが削除されると、開始時の対象リストと現在の表示リストがずれる → 開始時スナップショットを更新対象とし、反映時は同じ `ThreadId` がまだ存在する場合のみ UI リストを更新する。
- [Risk] 取得失敗タブがあると進捗が止まって見える → 成功・失敗にかかわらず対象タブの処理完了として `completed` を進め、成功時のみレス数と状態を更新する。
- [Risk] キャンセル後に部分更新結果が残る → 取得・保存済みのタブは反映済み状態として残し、未処理タブは既存状態を維持する。キャンセルはロールバックではなく以後の更新中断として扱う。
