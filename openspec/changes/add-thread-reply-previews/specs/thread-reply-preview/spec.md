# Spec Delta

## Purpose

番号順のスレッド本文を読み進めながら、返信先とそのレスへの返信内容を小さなインライン表示で確認できるようにする。会話の文脈を補助しつつ、NG非表示、既存ポップアップ操作、画像閲覧の契約を維持する。

## ADDED Requirements

### Requirement: 番号順の本体だけでの表示
システムは番号順のスレッド本体一覧だけで返信先と返信元のインラインプレビューを表示しなければならない（SHALL）。ツリー順、既存ポップアップ内、プレビュー内にはインラインプレビューを表示してはならない（MUST NOT）。通常レス本文そのものにプレビュー用の省略規則を適用してはならない（MUST NOT）。

#### Scenario: 番号順とツリー順を切り替える
- **WHEN** 対象レスのある本体一覧を番号順からツリー順へ切り替え、再び番号順へ戻す
- **THEN** プレビューは番号順でのみ表示され、ツリー順では通常のツリー表示を維持する

#### Scenario: プレビューからレスを開く
- **WHEN** プレビューをタップして既存ポップアップを開く
- **THEN** ポップアップには従来のレス表示が現れ、インラインプレビューは再帰的に追加されない

### Requirement: 安価だけの行から返信先を一件選ぶ
システムは行の前後空白を除く全内容が有効な安価または空白区切りの複数安価である行だけを返信先プレビューの挿入対象としなければならない（SHALL）。対象行を本文順に走査し、取得済みかつNGではない最初の参照先をレス全体で最大一件表示しなければならない（SHALL）。文中安価の行には挿入してはならない（MUST NOT）。

#### Scenario: 空白付き安価と複数安価の行
- **WHEN** 行が` >>1 `または`>>1 >>3`である
- **THEN** その行は挿入対象となり、有効な参照先から最大一件を表示する

#### Scenario: 文中安価を候補にしない
- **WHEN** 本文が`>>1 ありがとう`、改行、`>>2`であり、両参照先が表示可能である
- **THEN** 1の行には挿入せず、2の行に2のプレビューを表示する

#### Scenario: 最初の表示可能な候補まで進む
- **WHEN** 本文に`>>1,3`、改行、`>>4`があり、1がNGで3と4が表示可能である
- **THEN** 3のプレビューだけを最初の行の下に表示し、後続行には追加しない

#### Scenario: 表示可能な参照先がない
- **WHEN** 対象行の参照先がすべてNGまたは未取得である
- **THEN** 本文の安価行は維持し、空のプレビュー枠と省略件数を表示しない

### Requirement: 安価行と返信先プレビューのまとまり
システムは単一の`>>n`だけの対象行では、その安価番号と返信先プレビューを一つの視覚的な枠にまとめなければならない（SHALL）。範囲・カンマ・複数安価の対象行では安価行を保持し、その直下に独立したプレビュー枠を表示しなければならない（SHALL）。挿入の前後で元の本文の順序とリンク操作を維持しなければならない（SHALL）。

#### Scenario: 単一安価を一体化する
- **WHEN** `>>1`だけの行に1のプレビューを表示する
- **THEN** 安価番号を枠の見出し部分としてプレビューと一体化し、同じ安価行を別途重複描画しない

#### Scenario: 複数形式は安価行から分離する
- **WHEN** `>>1-5`、`>>1,3`または`>>1 >>3`の行にプレビューを表示する
- **THEN** 元の安価行はそのまま操作でき、その直下の独立した枠に一件だけ表示する

### Requirement: 返信元の選択と省略分の表示
システムは当該レスの本文・通常画像の下に、NG除外済み返信元をレス番号昇順で最大三件表示しなければならない（SHALL）。返信先・返信元とも上限を超える表示可能な候補がある場合は、残数を「ほか○件」で示し、対応する候補全件をポップアップで確認できるようにしなければならない（SHALL）。返信先の残数は安価だけの対象行に含まれる参照先全体から重複を除いて算出しなければならない（SHALL）。

返信元プレビュー群には「返信」や件数を示す見出しを置いてはならない（MUST NOT）。返信元の各項目は外側の囲み枠・塗りつぶし背景なしで表示し、左側の縦線と項目間の区切り線で構造を示さなければならない（SHALL）。返信元の「ほか○件」操作も塗りつぶし背景なしで表示しなければならない（SHALL）。返信先プレビューのカード外観は維持しなければならない（SHALL）。

#### Scenario: 返信元を見出しなしの引用風表示にする
- **WHEN** 返信元プレビューを一件以上表示する
- **THEN** 「返信」または返信件数の見出しを表示せず、各項目を左の縦線と項目間の区切り線で分け、外側の囲み枠・塗りつぶし背景なしで表示する
- **AND** 各項目のヘッダーはレス番号の数字から始め、「レス」や`>>`を前置しない

### Requirement: 返信元本文の親レス単一安価を省略する
システムは返信元本文全体に有効な安価tokenがちょうど一件だけ存在し、そのtokenが返信先（親レス）の番号だけを指定する単一安価である場合に限り、そのtoken直後に同じ行内で連続する空白とともに省略しなければならない（SHALL）。返信元本文の一行がそのtokenと空白だけで構成される場合、その行を表示してはならない（MUST NOT）。返信元本文全体に有効な安価tokenが二件以上存在する場合、システムは同じ行・別行を問わず親レス宛てのtokenを含む全tokenを変更してはならない（MUST NOT）。範囲・カンマ形式など複数番号を一つのtokenで指定する安価も、親レス番号を含んでいても変更してはならない（MUST NOT）。この加工は返信元プレビューだけに適用し、返信先プレビュー、通常レス本文、既存ポップアップ本文を変更してはならない（MUST NOT）。

#### Scenario: 唯一の親レス宛て単一安価を空白ごと省略する
- **WHEN** 返信元レス本文全体に安価tokenが一件だけあり、それが`>>38 ありがとう`で親レス番号が38である
- **THEN** 返信元プレビュー本文は`ありがとう`から始まり、安価tokenとその後の空白を含まない

#### Scenario: 親レス宛て単一安価だけの行を省略する
- **WHEN** 返信元本文全体の唯一の安価tokenが`>>38`だけの行にあり、親レス番号が38である
- **THEN** 返信元プレビューにその行を表示しない

#### Scenario: 同じ行の複数安価を全て保持する
- **WHEN** 返信元本文の同じ行に`>>38 >>40`があり、親レス番号が38である
- **THEN** `>>38`と`>>40`を含む行全体をそのまま返信元プレビューに表示する

#### Scenario: 別々の行の複数安価を全て保持する
- **WHEN** 返信元本文に`>>38`と`>>40`が別々の行にあり、親レス番号が38である
- **THEN** 両方の安価tokenと元の改行を保ち、どちらも省略しない

#### Scenario: 複数番号指定は省略しない
- **WHEN** 返信元レス本文に`>>38,40`または`>>38-40`があり、親レス番号が38である
- **THEN** その安価tokenと本文をそのまま返信元プレビューに表示する

#### Scenario: 他の表示経路は加工しない
- **WHEN** 同じ本文を通常レス、ポップアップ、または返信先プレビューとして表示する
- **THEN** 親レス番号への単一安価とその後の空白を省略しない

#### Scenario: 返信元の省略操作を背景なしで表示する
- **WHEN** 表示上限を超える返信元があり「ほか○件」を表示する
- **THEN** 省略操作は塗りつぶし背景なしで表示し、全返信元を開く操作性を維持する

#### Scenario: 返信先カード外観を維持する
- **WHEN** 返信先プレビューを表示する
- **THEN** 返信元専用の引用風外観を適用せず、従来の囲みカードとして表示する

#### Scenario: 返信元が五件ある
- **WHEN** NGでない返信元が2、4、6、8、10である
- **THEN** 2、4、6のプレビューと「ほか2件」を表示し、省略表示のタップで五件すべてを確認できる

#### Scenario: 返信先が複数行にある
- **WHEN** 安価だけの行の参照先が順に1、3、1、5であり、すべて表示可能である
- **THEN** 1だけをプレビューし「ほか2件」を示し、タップで1、3、5を確認できる

### Requirement: 小型ヘッダーと三行本文
システムはプレビューのヘッダーをレス番号の数字から始め、その後にデフォルトではない名前・IDを表示しなければならない（SHALL）。ヘッダーに「レス」や安価記号などの接頭辞を付けてはならない（MUST NOT）。日付は表示せず、本文だけを最大三行として超過部分を末尾省略しなければならない（SHALL）。板のデフォルト名と一致する名前は非表示とし、判定用の板設定を取得できない場合は名前を残さなければならない（SHALL）。文字は通常レスより小さくしつつ端末の文字拡大に追従しなければならない（SHALL）。ヘッダーにはヘッダー用、本文には本文用の文字サイズ設定をそれぞれ反映し、通常レスと同じユーザー行間設定を各文字サイズに対する比率として適用しなければならない（SHALL）。ヘッダーを太字にしてはならない（MUST NOT）。

#### Scenario: ヘッダーと本文の文字設定を個別に反映する
- **WHEN** ヘッダー用と本文用の文字サイズ設定が異なる状態でプレビューを表示する
- **THEN** ヘッダーと本文はそれぞれ対応する文字サイズ設定と通常レスの行間設定を反映し、ヘッダーは通常の太さで表示される
- **AND** それぞれの文字は対応する通常レスの表示より小さい

#### Scenario: ヘッダーはレス番号の数字から始まる
- **WHEN** 返信先または返信元のプレビューを表示する
- **THEN** ヘッダーは対象レス番号の数字から始まり、「レス」や`>>`を前置しない

#### Scenario: 2行以内の本文を省略しない
- **WHEN** プレビュー本文が利用可能な幅で2行以内に収まり、通常投稿行内に表示される
- **THEN** 本文の全内容を表示し、省略記号を付けない

#### Scenario: デフォルト名の長いレス
- **WHEN** 板のデフォルト名のレスをプレビューし、本文が四行以上に折り返される
- **THEN** ヘッダーにレス番号とIDだけを表示し、ヘッダーとは別に本文の先頭三行と末尾省略を表示する

#### Scenario: 独自名と設定取得失敗
- **WHEN** 名前がデフォルト名と異なる、または板のデフォルト名を取得できない
- **THEN** レス番号・名前・IDをヘッダーに表示し、設定取得の失敗でレスを非表示にしない

### Requirement: 本文右側への一枚サムネイル
システムはプレビュー本文から認識済みの画像URLをすべて除去し、画像があるときだけ本文の右側に先頭一枚のサムネイルを挿入しなければならない（SHALL）。画像はヘッダーと横並びにせず、その下に配置しなければならない（SHALL）。画像が複数の場合は追加枚数を「+N」と表示し、画像がないときは本文を全幅で表示しなければならない（SHALL）。

#### Scenario: 三枚の画像がある
- **WHEN** プレビュー対象に三つの画像URLが含まれる
- **THEN** 本文から三つとも除去し、ヘッダー下の右側に先頭画像と「+2」を表示する

#### Scenario: 画像なしと画像のみのレス
- **WHEN** 対象レスに画像がない、または画像URLだけが存在する
- **THEN** 画像なしでは右側を予約せず、画像のみでは空の本文三行を確保せずに右側サムネイルを表示する

### Requirement: プレビューと画像の操作
システムはプレビュー本体のタップで対象レスの既存ポップアップを開かなければならない（SHALL）。画像タップは本体タップと分離し、表示成功時だけ対象レスの全画像を既存ビューアへ渡し、先頭画像から閲覧できなければならない（SHALL）。読み込み中は遷移せず、既存の失敗種別ごとの表示・明示再試行可否を維持し、画像表示の文脈識別と失敗状態を他の表示箇所と取り違えてはならない（MUST NOT）。

#### Scenario: 追加画像をビューアで閲覧する
- **WHEN** 「+2」のある表示成功済みサムネイルをタップする
- **THEN** 対象レスの三枚すべてを持つビューアを先頭画像で開き、本体のレスポップアップは開かない

#### Scenario: 同じ画像が本体と複数プレビューに現れる
- **WHEN** 同じレスの画像が通常レスと別のレスのプレビューに同時表示され、プレビュー側から画像を開く
- **THEN** 遷移はタップしたプレビューの表示文脈を使用し、画像消失や別箇所への誤った遷移が起こらない

#### Scenario: 失敗サムネイルを再表示する
- **WHEN** 読み込み失敗したプレビュー画像をスクロールで再表示する
- **THEN** 失敗表示を維持し、タップによる明示再試行までは自動再取得しない

### Requirement: プレビュー操作のアクセシビリティ
システムはプレビュー本体、画像、省略件数を区別して読み上げ・フォーカス操作できるようにしなければならない（SHALL）。画像の総枚数と追加枚数、対象レス番号、開く対象を読み上げ可能にし、小型文字にしても操作領域の最小サイズを縮小してはならない（MUST NOT）。色だけで返信先・返信元や省略を示してはならない（MUST NOT）。

#### Scenario: 読み上げで省略分と画像を確認する
- **WHEN** 読み上げ機能でプレビュー本体、画像、「ほか2件」へ順にフォーカスする
- **THEN** 対象レスを開く操作、画像枚数を伴う閲覧操作、残りの返信を含む一覧操作を区別できる

#### Scenario: 文字拡大と狭い画面
- **WHEN** 大きな端末文字サイズで狭い画面に表示する
- **THEN** ヘッダーは必要に応じて折り返し、本文三行の上限、独立した画像操作、画面内レイアウトを維持する
