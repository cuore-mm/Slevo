## Requirements
### Requirement: 既存レス順を維持した新着グループ追加
システムは、スレッドのリロードで取得した新着レスを「更新単位のグループ」として末尾に追加し、既存レスの表示順を維持しなければならない（SHALL）。
この挙動は NUMBER/TREE の両方で適用し、グループ内の整形は現行ロジックを踏襲しなければならない（SHALL）。

#### Scenario: NUMBER で既存順を保ったまま新着を末尾へ追加する
- **WHEN** NUMBER 表示でスレッドをリロードし新着レスが取得される
- **THEN** 既存レスの順序は保持され、新着レスは末尾の新グループとして追加される

#### Scenario: TREE で既存順を保ったまま新着を末尾へ追加する
- **WHEN** TREE 表示でスレッドをリロードし新着レスが取得される
- **THEN** 既存レスの順序は保持され、新着レスは末尾の新グループとして追加される

### Requirement: 新着バーの表示位置を最新グループ先頭に固定
システムは、新着バーを最新の新着グループ先頭にのみ表示しなければならない（SHALL）。
新着レスが0件の更新では新着バーを表示してはならない（MUST NOT）。

#### Scenario: 最新グループ先頭に新着バーを表示する
- **WHEN** 新着レスが取得され、最新グループが末尾に追加される
- **THEN** 新着バーはそのグループの先頭にのみ表示される

#### Scenario: 新着0件の更新では新着バーを表示しない
- **WHEN** リロードで新着レスが取得されない
- **THEN** 新着バーは表示されない

### Requirement: 初回ロードでの未読グループ復元
システムは、閲覧履歴があり新着レスが存在するスレッドを初回ロードするとき、画面セッション開始時の最終既読レス番号の次を境界として既読グループと未読グループを構成しなければならない（SHALL）。システムは、復元した未読グループを初回ロードにおける最新グループとして扱わなければならない（SHALL）。

#### Scenario: 保存済み既読位置の次から未読グループを復元する
- **WHEN** 最終既読レス番号が100であり、110件のレスを初回ロードする
- **THEN** システムは1番から100番を既読グループ、101番から110番を未読グループとして構成し、101番レスの前に新着バーを表示する

#### Scenario: キャッシュされた最新レス数が古くても実取得レス数から復元する
- **WHEN** 閲覧履歴が存在し、キャッシュされた最新レス数と最終既読レス番号がともに100で新着件数が0と算出されているが、真の初回ロードで110件のレスを取得する
- **THEN** システムはキャッシュ新着件数を使用せず、101番から110番を未読グループとして構成し、101番レスの前に新着バーを表示する

#### Scenario: 最初の新着レス番号が保存されていなくても復元する
- **WHEN** 閲覧履歴の最初の新着レス番号が `null`、最終既読レス番号が100であり、110件のレスを初回ロードする
- **THEN** システムは最終既読レス番号を基準に101番から未読グループを構成する

#### Scenario: 未訪問スレッドでは復元しない
- **WHEN** 閲覧履歴が存在しないスレッドを初回ロードする
- **THEN** システムは初回未読グループを復元せず、新着バーを表示しない

#### Scenario: 全件既読では復元しない
- **WHEN** 最終既読レス番号が取得した最新レス番号以上である
- **THEN** システムは初回未読グループを復元せず、新着バーを表示しない

#### Scenario: 保存境界が取得範囲外の場合は復元しない
- **WHEN** 最終既読レス番号の次が実際に取得できたレス番号の範囲を超える
- **THEN** システムは空の未読グループを作らず、新着バーを表示しない

#### Scenario: 1番レスから未読として復元する
- **WHEN** 閲覧履歴が存在し、最終既読レス番号が0で、新着レス数が1件以上である
- **THEN** システムは取得レス全体を未読グループとして扱い、1番レスの前に新着バーを表示する

### Requirement: グループ状態の保持範囲
システムは、初回ロードで復元した未読グループとリロードで追加した新着グループの状態を、スレッドタブが閉じられるまで当該タブの画面セッション状態として保持しなければならない（SHALL）。画面セッション開始後に永続既読位置が更新されても、初回ロードで復元したグループ境界を変更してはならない（MUST NOT）。

#### Scenario: タブを閉じるまでグループが維持される
- **WHEN** 同一スレッドを複数回リロードして新着グループが追加される
- **THEN** 既存グループは保持され、最新グループのみが末尾に追加され続ける

#### Scenario: スクロールによる既読更新で初回境界を動かさない
- **WHEN** 初回未読グループを表示した後にユーザーがスクロールし、永続化された最終既読レス番号が進む
- **THEN** システムは表示中の初回未読グループ境界と新着バー位置を変更しない

#### Scenario: 後続更新では最新追加グループへバーを移す
- **WHEN** 初回未読グループを表示中のスレッドをリロードし、追加レスを取得する
- **THEN** システムは追加レスを末尾の新グループにし、新着バーをその最新グループ先頭にのみ表示する

#### Scenario: 新着0件の後続更新ではバーを表示しない
- **WHEN** 初回未読グループを表示中のスレッドをリロードし、新しいレスを取得しない
- **THEN** システムはグループ状態を保持しつつ新着バーを表示しない

#### Scenario: 0件取得後の回復では初回境界を再適用しない
- **WHEN** レス取得に一度成功した画面セッションで0件の成功結果を経由し、その後に非0件のレスを再取得する
- **THEN** システムは再取得したレスを単一グループとして復元し、画面セッション開始時の未読境界を再適用せず、新着バーを表示しない

#### Scenario: 初回0件取得後の非0件取得も回復として扱う
- **WHEN** 画面セッションの最初の成功結果が0件であり、その後に非0件のレスを取得する
- **THEN** システムは最初の成功結果で初回ロードが完了したものとして扱い、後続取得へ画面セッション開始時の未読境界を適用せず、新着バーを表示しない

#### Scenario: 非0件の取得数減少では単一グループへ回復する
- **WHEN** 読み込み済みレス数より少ない非0件のレスを再取得する
- **THEN** システムは取得結果を単一グループとして再構築し、初回未読境界を再適用せず、新着バーを表示しない

### Requirement: スレッド一覧の表示キー一意性
システムは、THREAD画面のレス一覧を描画する際、同一更新セッション内で同じレス番号が複数回表示される場合でも、`LazyColumn` の各表示行に一意なキーを割り当てなければならない（SHALL）。
この要件は TREE 表示および NUMBER 表示の両方に適用されなければならない（SHALL）。
投稿行のキーは、レス番号だけでなく、表示ロール、更新グループ、同一文脈内の出現位置を含む表示行 identity から生成されなければならない（SHALL）。
システムは、投稿の表示属性を表す中間モデルと、`LazyColumn` に渡す最終表示行モデルを分離し、最終表示行モデルが stable key を提供しなければならない（SHALL）。

#### Scenario: TREE表示で複数更新グループがある場合もキーが重複しない
- **WHEN** TREE表示でスレッドを複数回更新し、既存レスと新着グループの組み合わせにより同一レス番号が一覧内へ再登場する
- **THEN** 一覧内の各表示行キーは重複せず、描画処理は継続される

#### Scenario: キー重複が発生しないためクラッシュしない
- **WHEN** ユーザーがTHREAD画面を開いたまま更新を繰り返す
- **THEN** `Key "..." was already used` に起因する `IllegalArgumentException` は発生しない

#### Scenario: 同じレス番号のdimmed親行が複数グループに出現する
- **WHEN** TREE表示で同じ親レスが複数の新着グループに dimmed 親行として挿入される
- **THEN** それぞれの dimmed 親行は更新グループを含む別々の stable key を持つ

#### Scenario: 表示属性モデルと最終表示行モデルを分離する
- **WHEN** システムが投稿一覧を THREAD 画面の LazyColumn 用リストへ変換する
- **THEN** 投稿の表示属性は中間モデルで表現され、LazyColumn の key は最終表示行モデルの stable key から取得される
